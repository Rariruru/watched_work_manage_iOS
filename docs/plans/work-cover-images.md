# 作品画像 実装計画

## 目的

作品へ任意の画像1枚を設定し、作品一覧と作品詳細で見分けやすくする。対象は受け入れ基準41。

## 前提と非スコープ

- 本人が写真ライブラリから選ぶ。外部作品DBからのポスター自動取得は今回含めない
- 既存作品は画像なしのまま利用できる
- 画像の公開・共有は行わない
- 画像の著作権をアプリ側で判定する仕組みは作らない

## データとStorage

- `works.cover_path text null` を追加する
- 値は `{user_id}/{work_id}/cover.jpg` だけを許す
- 非公開バケット `work-covers` を作り、1ファイル10MB・JPEGだけを許す
- StorageのRLSは先頭フォルダが本人のIDと一致する場合だけ読み書きを許す
- 作品削除とアカウント削除ではStorage実体も削除する

## 実装順序

1. マイグレーションで列、制約、バケット、Storage RLSを追加する
2. ドメイン型と作品APIへ画像パス・期限付きURL・アップロード／削除を追加する
3. 作品追加・編集へ1枚用画像選択UIを追加する
4. 作品一覧・詳細へ画像を表示し、画像なしは既存のプレースホルダーを使う
5. アカウント削除Functionを `work-covers` に対応させる
6. テスト、型検査、Lint、Web書き出し、差分確認を行う

## 失敗時の扱い

- 画像の選択をキャンセルしても入力を変えない
- 権限拒否時は画像なしで保存でき、設定アプリへの案内を出す
- 10MB超過またはサイズ不明の画像は追加しない
- 新規作品の画像保存に失敗した場合は作成した作品をロールバックし、成功通知を出さない
- 編集時の画像保存に失敗した場合は画面に入力を残し、成功通知を出さない

## 移行とロールバック

- nullable列の追加なので既存データの書き換えはない
- アプリより先にマイグレーションを適用する
- ロールバック時はアプリの画像導線を先に戻し、Storage実体を確認してから列とバケットを削除する

## 検証

- 画像あり／なし／変更／取り外しを確認する
- 10MB超過、写真権限拒否、通信失敗を確認する
- 作品削除・アカウント削除でStorage実体が残らないことを確認する
- 別利用者が期限付きURLを作成できないことを確認する
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run export:web`

- `npm run lint`、`npm run typecheck`、`npm test`（26件）、`npm run export:web` は成功した

- 本番マイグレーション適用と `delete-account` Functionの再デプロイは人間が行う
