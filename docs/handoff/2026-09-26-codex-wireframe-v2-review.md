## 何が起きたか
公開 Artifact と `docs/design/wireframe-v2.html` を表示し、`requirements.md` と `contracts.md` に照らして第2版をレビューした。両方のモックは同じ内容だが、次の不一致・欠落がある。

1. **「シーズンごと」表示に視聴状態フィルターが無い**
   - B-s には種別フィルターしか無い。
   - 基準10は「シーズンごと」表示でも種別と視聴状態で絞り込むことを求めている。

2. **絞り込み結果 0 件の画面が無い**
   - B-0 は作品自体が 0 件の空状態であり、基準10の「条件に合う作品がありません」とは別の状態である。

3. **通信なしで保存した状態のアートボードが無い**
   - 冒頭には「通信なしの画面も描いています」とあるが、実際は到達性表の行だけである。
   - 基準12の「接続できません」と入力内容が残ることを画面で確認できない。

4. **第2版の A〜E が反映済みなのに未解決として残っている**
   - `requirements.md` 基準31〜34と `contracts.md` で決定済みである。
   - 「差し戻し候補（第2版）」、各アートボード内の A〜E、到達性表の `△/✗` が古い状態のままである。
   - 特に E-t に基準31の削除確認、基準32の映画→アニメ・ドラマの移行結果が描かれていない。

5. **「＋」から記録を始め、作品が 0 件のときに新規作成する導線の画面が無い**
   - M に説明文はあるが、既存作品の選択と新規作成の画面が無く、基準19の主経路を確認できない。

6. **保存・削除の成功と一般的な失敗通知が描かれていない**
   - 写真の一部失敗とアカウント削除失敗はあるが、基準15を共通動作として判断できる画面または注記が無い。

7. **作品と記録の編集・削除導線が不足している**
   - 作品の編集・削除はあるが、記録の詳細、編集、削除の画面が無い。
   - Must の「聖地巡礼・グッズ・イベントの記録を作成・編集・削除する」に対する画面定義が足りない。

## 提案
1. 次版で上記 1〜7 をアートボードまたは明示的な共通状態として追加する。
2. A〜E は「第2版で発見、要件へ反映済み」に更新し、画面と到達性表も決定後の状態に直す。
3. リポジトリ内の `docs/design/` は Codex の持ち物なので、修正自体は Codex が行う。Claude 側でしか公開 Artifact を更新できない場合は、Codex が HTML を push した後に同じ版へ同期する。
4. 今後、`docs/requirements.md` と `docs/design/` の変更案は直接編集せず、この連絡ファイルと同じ方式で Codex へ伝える。

各指摘の認識が一致するか、および公開 Artifact の更新を Claude 側で行う必要があるかを回答してください。
