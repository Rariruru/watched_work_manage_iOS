## 何が起きたか

上田が決めたこと（2026-09-26）:
- UI の実装方式は **Expo**（SDK 57 ＋ Expo Router ＋ TypeScript）。理由: 開発機が Windows で SwiftUI をビルドできない。前作も Expo
- 最初の範囲は「基盤＋作品の登録」: Apple でサインイン・サインアウト・アカウント削除・規約の入口、作品とシーズンの登録・一覧・編集・削除
- 評価・感想・記録（聖地巡礼・グッズ・イベント）・写真は、この範囲に入れない（評価の刻みなどが未決のため）

実装した受け入れ基準: 1・2・3・4・5・10・11・12・13・14・15・16・17・18・23・24・26・28・33・34、31・32 のうち評価以外の部分。
- Web で動きを確かめた: 1（未ログインでは奥の画面に入れない）・3（削除に失敗したときの表示）・5・12・13・16。Supabase が無いので、保存が**成功する**経路はまだ一度も通していない
- 単体テストで確かめた（`src/domain/works.test.ts`）: 5・10・18・24・26・28・31・32・33・34 の判断の部分
- 14 は RLS を書き、確認用の SQL を `supabase/tests/rls_check.sql` に置いた（未実行）
- 実機（iPhone）では何も確かめていない

## 提案（Codex に反映してほしいこと）
1. **`requirements.md` §7**: 「UI の実装方式」を決定済みに移す（Expo、2026-09-26 上田）。変更履歴にも書く
2. **`contracts.md`「列挙値」**: スキーマで使った綴りを書き戻す（DB の check 制約と `src/domain/types.ts` がこの綴り）
   - 作品の種別: `anime` / `drama` / `movie`
   - 視聴状態: `want` / `watching` / `watched`
3. **`contracts.md`「種別の変更」との食い違いを決めてほしい**: 「アニメ・ドラマ → 映画: 映画の視聴状態は空で始まる」とあるが、視聴状態は3値のどれかで、空を持てない。実装では **「観た」で始める**ようにした（`supabase/migrations/…_works_and_seasons.sql` の `change_work_type`）。これでよいか、別の値にするか
4. **`contracts.md`「作品」の重複判定**: 実装は「前後の空白を除いて完全一致」。全角半角・大文字小文字は同一視していない（`src/domain/works.ts` の `findDuplicate`）。今の「未定」のままでよいが、決めたら教えてほしい
5. 仮で置いたもの（どれも後で変えられるが、Bundle ID だけは App Store に出した後は変えられない）:
   - アプリ名「観た作品ノート」（`app.json` の `name`）
   - Bundle ID `com.tiffanysho.watchedwork`
   - 利用規約・プライバシーポリシーの URL は未設定（押すと「準備中」）
6. 基準27（評価の付いた話が消える確認）は、各話の評価を作るときに足す。今は話に評価が無いので確認を出していない
7. 次の範囲（感想・評価）の前に、**評価の刻み（1〜5 の整数か 0.5 刻みか）** を決めて、`docs/plans/` に計画を書いてほしい。今度は計画を待ってから始める
